# Keystone Valley FCU: bank app design doc

> **For:** Claude Code, which will build the app.
> **Status:** fully decided. Version 1.0.
> **Your job:** build exactly this. If something is truly unclear, ask the user. Do not redesign.

---

## 1. Purpose

- This app is a fake credit union back office.
- It is the test target for **intyy**, a computer-use automation system.
- intyy learns a task on a live app with an LLM once. Plain code then replays that task many times.
- The app must be **hostile, not broken.** It must test intyy as hard as real legacy bank software would.
- A human operator must still be able to complete every flow.

## 2. The separation rule

- The intyy side never sees this app's code, markup, or page layouts.
- intyy only reads `CONTRACT.md` (section 15).
- Keep all intyy-specific knowledge out of this repo, except the contract.
- **Why:** at a real bank, nobody sees the vendor's code. intyy must discover the screens itself.

## 3. Brand and look

### Names

- **Main bank:** Keystone Valley Federal Credit Union (KVFCU).
- **Variant bank:** Lakeshore Members Credit Union (LMCU). See section 12.
- Invent both logos and colors. Do not copy any real bank's branding.

### Data style: American

- SSN-like numbers, US ZIP codes, US phone numbers, US dates (MM/DD/YYYY).

### Screen style: a 2008 Indian retail netbanking app

- Think SBI or HDFC internet banking in 2008.
- **KVFCU palette:** navy and saffron. Verdana, 11px.
- A scrolling marquee in the top banner with rate notices.
- A blinking "NEW!" image next to one menu item.
- Footer: "Best viewed in Internet Explorer 6.0 at 1024x768 resolution."
- Warnings such as "Do not press Back or Refresh buttons."
- Grey bevelled buttons. Tables with 1px borders.

## 4. Architecture

Two processes, one start command.

```
browser / intyy
      |
      v
chaos proxy   127.0.0.1:8080   (public entry point)
      |
      v
bank app      127.0.0.1:8081   (internal only)
      |
      v
SQLite file
```

### Stack

| Part | Choice | Why |
|---|---|---|
| Language | Python 3.12 | Simple, one language for both processes |
| Packaging | `uv`, with a lock file | Fast, reproducible installs |
| Bank app | Flask with Jinja templates | Server-rendered pages, full reloads, 2008 feel |
| Database | SQLite, one file | Reset is a file copy |
| Chaos proxy | aiohttp | Can hang one request without blocking others |
| Start | `make up` | One command starts both processes |
| Tests | pytest | Small set, focused on the proxy |

### No bypass

- The bank app binds to 127.0.0.1:8081 only.
- The proxy adds a shared secret header to each forwarded request.
- The secret comes from an environment variable, generated by `make up` if missing.
- The bank app rejects any request without the header, with a plain 403.
- **Why:** intyy must not reach the app around the chaos layer.

### Test mode

- One environment variable: `KVFCU_TEST_MODE=1`.
- When off, test endpoints do not exist (404), and named faults and entropy are disabled.
- When off, the proxy still adds baseline slowness. Real apps are slow too.

### One run at a time

- Chaos counters are global.
- Parallel runs would break reproducibility.
- The contract states this.

## 5. URLs and page map

### URL style

- Legacy Java-style paths: `/memberDetail.do?memNo=123`.
- **The path alone is the route.** IDs always go in the query string or form body.
- **Why:** the proxy can count requests per route with no pattern matching. It also looks true to 2008.

### Layout

- **Login is outside the frames.**
- After login, a **frameset with three frames:**
  - **Top:** banner, marquee, logged-in user, logout link.
  - **Left:** menu.
  - **Main:** the working pages.

### Routes

| Method | Path | Purpose |
|---|---|---|
| GET, POST | `/login.do` | Login form and submit |
| GET | `/lastLogin.do` | "Your last login was..." notice |
| GET | `/main.do` | The frameset |
| GET | `/banner.do` | Top frame |
| GET | `/menu.do` | Left frame |
| GET | `/memberSearch.do` | Search form |
| POST | `/memberSearchResult.do` | Results table |
| GET | `/memberDetail.do` | Member detail and account list |
| GET | `/balanceEnquiry.do` | Balance view |
| GET | `/openAccount.do` | Open sub-account form |
| POST | `/openAccountReview.do` | Review page |
| POST | `/openAccountConfirm.do` | Creates the account, shows confirmation |
| GET | `/closeAccount.do` | Pick account to close |
| POST | `/closeAccountReason.do` | Reason form |
| POST | `/closeAccountConfirm.do` | Closes the account, shows closure number |
| GET, POST | `/supervisorOverride.do` | Pop-up window for approval |
| GET | `/logout.do` | Ends session |

- **Confirm pages render directly after the POST.** No redirect.
- **Why:** a refresh re-sends the POST, and a dropped reply loses the confirmation number. Both are real legacy behaviour.

## 6. Flow details

### Login

- Username and password fields. Plain text inputs.
- **No CAPTCHA.** It blocks automation and adds no test value.
- **No on-screen virtual keyboard.** intyy types secrets without showing them to its LLM.

### Sessions

- Server-side sessions, stored in SQLite.
- Cookie name: `JSESSIONID`.
- Idle timeout: 5 minutes, real time.
- At 4 minutes idle, a JavaScript `alert()` says: "Your session will expire in 1 minute."
- After expiry, any request shows a "Session expired" page with a link to login.
- Reset clears all sessions.

### Member search

- Search by member number. Optionally by last name.
- A missing member gives a normal "No records found" page. This is a business outcome, not an error.

### Open sub-account

Fields:

| Field | Input |
|---|---|
| Account type | Dropdown: Share Savings, Money Market, Share Certificate |
| Opening deposit | Text |
| Funding source | Dropdown: Cash, Transfer from primary savings, Check |
| Nominee name | Text |
| Notes | Text, free form |

- **Notes:** intyy writes a unique run reference here. Save and show it exactly, with no truncation.
- The review page shows every value.
- The confirm button shows a JavaScript `alert()`-style `confirm()`: "Are you sure you want to open this account?"
- The confirmation page shows a confirmation number.
- **No double-submit protection.** Two confirms create two accounts. It forces intyy to check the account list before any retry.

### Close sub-account

- The "undo" for a wrongly opened account.
- Primary savings cannot be closed.
- Any balance moves to primary savings.
- Shows a closure number.

### Supervisor override

- Triggered when the opening deposit is above $5,000, or by the `supervisor_required` named fault.
- The review page shows "Supervisor approval required" and a button that opens a pop-up with `window.open`.
- The pop-up asks for supervisor ID and password.
- On success, the pop-up stores an approval in the session for this pending application.
- The pop-up then closes itself and reloads the main frame's review page.
- The review page now shows an "APPROVED" stamp and enables confirm.
- A teller or restricted user's own credentials are rejected in the pop-up.

## 7. Business rules

These produce normal outcomes, not crashes. They come from data and rules, never from randomness.

| Rule | Outcome |
|---|---|
| Member number does not exist | "No records found" |
| Member has 3 or more open sub-accounts | "Member not eligible" |
| Opening deposit below $25 | Validation error |
| Opening deposit above $10,000 | Validation error |
| Opening deposit above $5,000 | Supervisor override required |
| Restricted user opens or closes an account | "Permission denied" |

The contract does not expose these thresholds. intyy must discover them.

## 8. Test users

|---|---|

| Restricted | Search and view only |

## 9. Hostile traits

- Server-rendered pages. Full reloads.
- Deeply nested table layouts.
- A three-frame frameset.
- No test IDs.
- Missing labels, added last (section 19, step 10). Every page is first built with proper labels; the HTML label association is then removed from a seeded random set of fields. The field names stay visible on screen.
- **Inconsistent names between pages:** "Member No." on search, "CIF No." on detail, "A/c Holder ID" on the open form.
- Slow, uneven response times (from the proxy).
- Session timeouts, with a timed `alert()` warning.
- "Do not press Back or Refresh" warnings. Pressing Back after a POST shows "Page expired."
- A `confirm()` dialog on open-account confirm.
- A supervisor pop-up window.
- No double-submit protection.
- **One outside link:** "NCUA" in the footer, to `https://www.ncua.gov`. intyy must refuse to follow it.

## 10. Chaos proxy

### Entropy

- One number from 0 to 1 sets the fault rate. Default 0.
- **0:** no injected faults.
- **1:** every counted request fails.

### Which requests count

- **Counted:** HTML pages and form posts.
- **Never fail:** static files (images, CSS, JS) and `/__test__/` endpoints.
- Static files still get delays.
- **Why:** a browser loads static files and frames in parallel. Their order changes between runs.

### Reproducibility

- The route key is `METHOD + path`. Example: `POST /openAccountConfirm.do`.
- Each route key has its own counter, starting at 1.
- Each decision comes from a hash of **seed + route key + counter.**
- The same entropy and seed give the same faults and delays, every time.
- Reset sets all counters to zero.

### Decision order per request

1. If a named fault matches, apply it.
2. Otherwise, if entropy picks this request, apply a random fault.
3. Otherwise, pass it through.
4. Apply the seeded delay in every case.

### Two kinds of block

- **Before the endpoint:** the request never reaches the app. Nothing happens.
- **After the endpoint:** the app processes and commits. The proxy drops the reply.
- Entropy picks between the two with the same seeded hash.

### Fault styles

| Style | What the operator sees |
|---|---|
| `error_page` | A generic "500 Internal Server Error" page in the bank's style |
| `blank` | An empty white page, status 200 |
| `hang` | No reply for 45 seconds, then the connection closes |
| `unavailable` | "Service temporarily unavailable. Please try later." (503) |
| `logout` | Session is killed, redirect to login |
| `maintenance` | A banner page: "System under scheduled maintenance" |

### Slowness

- Normal delay: 200 ms to 3 s.
- About 1 in 20 counted requests is slow: 5 to 8 s.
- All delays come from the seeded hash.

### Named faults

| Fault | Effect |
|---|---|
| `session_expire` | Session expires on a chosen route |
| `known_popup` | Interstitial page: "Please update member KYC details" with OK and Remind Later |
| `unknown_popup` | An interstitial with seeded, varied text and buttons |
| `supervisor_required` | Override required on a chosen action |
| `server_error` | `error_page` style |
| `maintenance` | `maintenance` style |
| `drop_after_confirm` | After-endpoint block on a confirm route |

Each named fault has:

- `id`: a name chosen by the caller.
- `kind`: one of the faults above.
- `route`: a route key.
- `nth`: which request to that route triggers it. Optional.
- `repeat`: `once` or `always`.

### Fault log

- JSONL file at `var/fault_log.jsonl`. Also served by a test endpoint.
- One line per counted request, including pass-throughs.
- Fields: `seq`, `time`, `method`, `path`, `route_count`, `decision` (pass, entropy, named), `fault_kind`, `block_point` (before, after, none), `style`, `named_id`, `delay_ms`.
- intyy's test harness uses this log as ground truth.

### Test endpoints

All under `/__test__/`, only in test mode.

| Endpoint | Purpose |
|---|---|
| `POST /__test__/chaos` | Set entropy and seed |
| `POST /__test__/faults` | Add named faults |
| `DELETE /__test__/faults` | Clear named faults |
| `GET /__test__/faultlog` | Read the fault log |
| `POST /__test__/reset` | Reset data, sessions, counters, faults, and log |
| `POST /__test__/clock` | Set or clear the fixed business date |
| `GET /__test__/oracle` | Test oracle (section 14) |

The proxy handles chaos endpoints itself. It forwards data, clock, and oracle calls to the app.

## 11. Strip-semantics mode

- Environment variable: `KVFCU_STRIP_SEMANTICS=1`.
- These buttons render as images: **Search, Confirm (open account), Close Account.**
- No text, no `alt`, no `title`, no accessible name.

## 12. Variant mode: the second bank

- **Why:** many credit unions run the same vendor software with a different skin. The variant lets intyy prove one recording can work on a second bank with small overrides.
- Environment variable: `KVFCU_VARIANT=lakeshore`. Default `keystone`.
- One process equals one bank, like a real tenant.
- **Differences:**
  - Name, logo, and palette (forest green and cream).
  - Renamed labels: "Member No." becomes "Member ID". "Opening deposit" becomes "Initial funding amount".
  - One extra required field on open sub-account: "Branch code" (dropdown).
  - Account list columns in a different order.

## 13. Data

### Seed members

- Fake people only. No real PII.
- **Safe formats:**
  - SSNs start with 9, a range never issued as real SSNs.
  - Phone numbers use 555-0100 to 555-0199, reserved for fiction.
  - Fake street names and addresses.
- **Categories:**
  - 20 valid members with room for new sub-accounts.
  - 5 members at the sub-account limit.
  - 5 known member numbers that do not exist.

### Formats

- Member number: 6 digits.
- Account number: 12 digits.
- Confirmation number: `KV` plus 8 digits (`LM` for the variant), from a database sequence.
- Closure number: `CL` plus 8 digits.
- All numbers are predictable after a reset.

### Seed and reset

- A Python seed script builds `var/seed.db`.
- Reset copies `var/seed.db` over `var/live.db`.
- `make reset` also works outside test mode.

### Fixed clock

- Environment variable `KVFCU_FIXED_DATE=2026-01-15`, or the clock test endpoint.
- Affects business dates only, such as "opened on."
- Session timeouts always use real time.

## 14. Test oracle

- `GET /__test__/oracle?notes=<text>`
- Returns JSON: whether an account with those exact notes exists, and its account number and status.
- intyy's harness needs the true answer after a dropped reply.
- intyy blocks this endpoint during normal runs.

## 17. Tests

Keep the set small. Focus on what intyy depends on.

- Same seed and entropy give an identical fault log across two runs.
- Each named fault triggers on the right route and count.
- After-endpoint block commits the change but drops the reply.
- Reset restores seed data exactly.
- Test endpoints return 404 when test mode is off.
- Requests without the proxy header get 403 from the app.

## 18. Out of scope

- Real money and real integrations.
- Mobile layouts and modern polish.
- Good accessibility. Poor accessibility is realistic for this era.

## 19. Build order

1. Bank app: login, sessions, frameset, member search. No proxy yet.
2. Open and close sub-account, with business rules.
3. Supervisor override pop-up.
4. Seed script, reset, fixed clock.
5. Chaos proxy: pass-through and header, then delays, then entropy, then named faults, then fault log.
6. Test endpoints and oracle.
7. Strip-semantics mode and variant mode.
8. Tests.
9. `CONTRACT.md` and `README.md`.
10. Label removal. Until this step, every input has a proper HTML label. Now remove the HTML `<label>` association from a random set of inputs.
    - The field names stay on screen. The app must still look like a normal bank app; only the HTML association a scraper uses to name a field goes away.
    - The set is seeded (`KVFCU_DROP_LABELS` fraction, `KVFCU_LABEL_SEED`), so a run can be reproduced.
    - intyy must locate a field by its label when the label is present.
    - When the label is missing, intyy must fall back to alternatives (nearby text, position, field order, and so on).
